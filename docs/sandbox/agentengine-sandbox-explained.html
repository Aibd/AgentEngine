场景一 · 信任边界在哪里

左边是你 现在 的形态，右边是 文档 主张的形态。同一段不可信代码，区别只在它跑在哪个盒子里。 点下面切换，看边界出现 / 消失。

🖥️ 宿主机 · 同一个 OS / 同一个用户 / 同一份环境变量&密钥
Agent App（可信）
TurnRunner · ToolExecutor · ExecPolicy
这是你自己的代码，控制端
不可信代码（LLM 生成）
bash 工具 = 直接 subprocess
就在 Agent 进程的主机上跑
⚠ 没有信任边界 —— 两者共享一切
可信（你的代码） 不可信（生成的代码） 🔓 边界缺失：代码能读你的密钥、写整台机器、连外网
🖥️ 宿主机
Agent App（可信，留在主机）
TurnRunner · ToolExecutor
当指挥官，按需创建/销毁容器
SandboxManager
通过 Docker SDK 拉起会话容器
🛡️ 沙盒容器 · 隔离边界
不可信代码在这里跑
network off · cap drop ALL
non-root · cgroup 限额 · 只读 rootfs
跑不出这个盒子
可信端（主机） 不可信代码（容器内） 🛡️ 内核/系统调用层隔离：逃逸≈攻破容器 runtime
观察同一动作在两种结构下的不同结局

场景二 · 一次请求的完整数据流

文档第二节那条链路，跑成动画。小球沿路走：蓝=请求 → 黄=生成的代码 → 绿=结果。 关键：代码那一棒进的是会话容器，对 ToolExecutor 以上完全透明。

①→②→③ 生成代码，④ 过策略闸门，⑤ 进容器跑，结果原路返回

场景四 · 会话容器的生命周期

文档的"会话容器"模型：一个 conversation 一个容器，建一次、反复 exec、状态驻留、结束销毁。 点 ▶ 走一遍会话。

建容器那笔贵开销，一个会话只付一次；变量在 exec 之间保留

场景五 · 沙盒到底接在哪一层

一句话：接在 Tool 抽象这一层。下面是你的实际分层， 绿=已有、黄=软约束、蓝=要新增。 点 ▶ 高亮改动点 看哪些动、哪些不动。

TurnRunner · run_turn（运行编排）
只跟 Tool.run() 抽象打交道 → 换不换容器它无感
✓ 已有 · 不动
ToolExecutor（超时 / 事件 / 准入）
在工具运行前调 ExecPolicy；包 asyncio 超时
✓ 已有 · 不动
ExecPolicy（Allow / Deny / Ask）
字符串前缀匹配 —— 是真实分层，但不能当安全边界
~ 软约束 · 建议收紧
⭐ Tool 抽象 ← 沙盒的落点
新增 SandboxedBashTool：同名 "bash"，把执行下沉到容器
＋ 新增实现
SandboxManager（容器生命周期）
与 ConversationLockManager 同级；带安全清单参数
＋ 新增（运行编排层）
BashTool（现状：直接 subprocess）
保留，本地/信任场景用；生产换成 SandboxedBashTool
~ 保留 · 部署期二选一
核心不动、不依赖 Docker；隔离作为部署期可插拔实现接入
