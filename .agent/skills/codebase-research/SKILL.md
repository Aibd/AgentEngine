# 调研流程

按以下三步执行,**不要跳步**:

## 1. 摸清结构

先用 `read_file` 读这些路径(都是相对工作区根的相对路径):

- `README.md` — 项目说明
- `pyproject.toml` 或 `package.json` — 依赖与构建配置
- `src/` 或 `app/` 下的目录列表(可以读 `__init__.py` 推断)

如果某个文件不存在,工具会返回 "Error: file not found",这不是失败,直接跳过。

## 2. 读关键模块

根据 README 提到的入口/核心组件,挑 **2~5 个最重要的文件**用 `read_file` 读取。
判断标准:出现在 README 路径示例里的、或文件名是 `main.py` / `app.py` / `service.py` / `__init__.py`。

每个文件读完不要立刻总结,先记下"这个文件做什么"。

## 3. 产出报告

最终回答必须包含:

- **一句话定位**:这个项目是做什么的
- **架构分层**:列 3~6 个核心模块,每个一句话说清职责
- **入口与扩展点**:用户/开发者从哪里开始改起
- **风险或缺失**:你读完之后觉得哪里不清楚或有疑问

格式用 Markdown,标题层级 `##`。

## 输入参数

用户调用时传的内容:`${ARGUMENTS}`

把上面这段当成用户的具体诉求(可能为空,空就走默认流程)。
