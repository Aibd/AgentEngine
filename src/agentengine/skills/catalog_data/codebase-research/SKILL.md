# 调研流程

按以下三步执行，**不要跳步**：

## 1. 摸清结构

先读这些路径（相对工作区根）：

- `README.md` — 项目说明
- `pyproject.toml` / `package.json` — 依赖与构建配置
- `src/` 或 `app/` 下的目录列表

文件不存在不是失败，直接跳过。

## 2. 读关键模块

根据 README 提到的入口/核心组件，挑 **2~5 个最重要的文件**读取。优先：`main.py` / `app.py` / `service.py` / `__init__.py`，以及 README 路径示例里出现的文件。

每个文件读完先记下"这个文件做什么"，不要立刻总结。

## 3. 产出报告

最终回答必须包含：

- **一句话定位**：这个项目做什么。
- **架构分层**：3~6 个核心模块，每个一句话说清职责。
- **入口与扩展点**：从哪里开始改起。
- **风险或缺失**：读完后觉得哪里不清楚。

格式用 Markdown，标题层级 `##`。

## 输入参数

用户的具体诉求（可能为空，空就走默认流程）：`${ARGUMENTS}`
